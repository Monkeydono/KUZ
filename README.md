# KUZ ระบบจองห้องประชุม Zoom มหาวิทยาลัยเกษตรศาสตร์

ระบบสำหรับให้นิสิตและบุคลากรจองห้องประชุม Zoom ของมหาวิทยาลัยผ่านเว็บไซต์ ระบบจะสร้างห้องประชุม Zoom ให้อัตโนมัติ ส่งอีเมลแจ้งเตือน บันทึกนัดหมายลง Google Calendar และเก็บไฟล์บันทึกการประชุมไว้ใน Google Drive ของผู้จอง

เว็บไซต์จริงอยู่ที่ https://meet.ocs.ku.ac.th

เอกสารนี้แบ่งเป็น 2 ส่วน

- ส่วนที่ 1 คู่มือผู้ใช้งาน สำหรับนิสิต บุคลากร และผู้ดูแลที่อนุมัติการจอง
- ส่วนที่ 2 คู่มือผู้ดูแลระบบ สำหรับผู้ที่จะพัฒนาและดูแลระบบต่อ

# ส่วนที่ 1 คู่มือผู้ใช้งาน

## การเข้าสู่ระบบ

ผู้ที่ยังไม่เข้าสู่ระบบดูปฏิทินห้องประชุมได้ เห็นช่วงเวลาที่ถูกจองและหัวข้อการประชุม แต่ต้องเข้าสู่ระบบก่อนจอง หัวข้อการประชุมจึงเป็นข้อมูลที่ทุกคนเห็น ไม่ควรใส่ข้อมูลลับ

เข้าสู่ระบบได้ทางเดียวคือปุ่มเข้าสู่ระบบด้วย KU ALL-Login ใช้บัญชีนนทรีเดียวกับระบบอื่นของมหาวิทยาลัย ระบบจะบันทึกประเภทบุคคลและหน่วยงานไว้เพื่อทำสถิติ

ครั้งแรกหลังผ่าน KU ALL-Login ระบบจะพาไปหน้า Google ต่อให้เอง ให้เลือกบัญชี Google ของมหาวิทยาลัย @ku.th ที่เป็นอีเมลเดียวกับบัญชีนนทรี และกดอนุญาตสิทธิ์ Google Calendar และ Google Drive ทั้งหมด บัญชี Gmail ส่วนตัวหรือบัญชี @ku.th ของคนอื่นใช้ไม่ได้ ครั้งต่อไปไม่ต้องทำขั้นนี้อีก

เข้าเว็บครั้งแรกจะมีหน้าต่างประกาศความเป็นส่วนตัวขึ้นมา อ่านแล้วกดรับทราบหนึ่งครั้ง

ระบบจะจำการเข้าสู่ระบบไว้ในเครื่อง เปิดเว็บครั้งต่อไปใช้งานได้ทันทีโดยไม่ต้องเข้าสู่ระบบใหม่ ถ้าไม่ได้ใช้งานนานเกิน 30 วัน หรือกดออกจากระบบ จึงต้องเข้าสู่ระบบอีกครั้ง โดยใช้ KU ALL-Login หรือ Google อย่างใดอย่างหนึ่งก็ได้ และไม่ต้องกดอนุญาตสิทธิ์ซ้ำ

ระบบเปิดให้เฉพาะอาจารย์ บุคลากร และนิสิตปัจจุบัน บัญชีศิษย์เก่าและบัญชีบุคคลภายนอกเข้าใช้งานไม่ได้ อีเมลส่วนตัวเช่น @gmail.com ก็เข้าไม่ได้

เมื่อใช้งานเสร็จให้กดปุ่มออกจากระบบทุกครั้ง โดยเฉพาะเมื่อใช้เครื่องคอมพิวเตอร์ส่วนกลาง

## เมนูหลัก

| เมนู | ใช้ทำอะไร |
|---|---|
| ปฏิทิน | ดูช่วงเวลาที่ว่างและที่ถูกจองแล้วของแต่ละวัน และจองห้องจากหน้านี้ได้ทันที กดที่ชื่อเดือนเพื่อเลือกเดือนและปีได้ |
| คู่มือการใช้งาน | เปิดเอกสารคู่มือฉบับเต็ม |
| จองห้อง | กรอกรายละเอียดเพื่อจองห้องประชุม |
| การจองของฉัน | ดูรายการที่จองไว้ เข้าห้องประชุม ยกเลิกการจอง และดาวน์โหลดไฟล์บันทึกการประชุม |
| กระดิ่งแจ้งเตือน | ดูการแจ้งเตือนภายในเว็บ เช่น ผลการอนุมัติ หรือไฟล์บันทึกการประชุมพร้อมแล้ว |
| ผู้ดูแลระบบ | แสดงเฉพาะผู้ที่มีสิทธิ์ staff หรือ admin |

## ขนาดห้องประชุม

| ห้อง | รองรับ | ระยะเวลาต่อครั้ง | ต้องรออนุมัติ |
|---|---|---|---|
| Room 100 | ไม่เกิน 100 คน | ไม่เกิน 40 นาที | ไม่ต้อง ใช้งานได้ทันที |
| Room 300 | ไม่เกิน 300 คน | ไม่เกิน 24 ชั่วโมง | ต้องรอผู้ดูแลอนุมัติ |
| Room 1000 | ไม่เกิน 1000 คน | ไม่เกิน 24 ชั่วโมง | ต้องรอผู้ดูแลอนุมัติ |

ห้องที่รองรับเกิน 100 คนใช้บัญชี Zoom แบบเสียค่าใช้จ่ายซึ่งมีจำนวนจำกัด จึงต้องผ่านการอนุมัติก่อน

## เงื่อนไขการจอง

- จองได้ตั้งแต่เวลา 08.00 น. ถึง 24.00 น. ของวันเดียวกัน
- จองล่วงหน้าได้ไม่เกิน 30 วัน และจองย้อนหลังไม่ได้
- ผู้ใช้ทั่วไปจองได้ 4 ครั้งต่อเดือน นับตามเดือนของวันประชุม
- หัวข้อการประชุมยาวได้ไม่เกิน 200 ตัวอักษร
- ช่วงเวลาที่มีผู้อื่นจองห้องเดียวกันไว้แล้วจะจองซ้ำไม่ได้

## ขั้นตอนการจอง

1. ไปที่หน้าปฏิทินหรือหน้าจองห้อง
2. เลือกวันที่ เวลาเริ่ม เวลาสิ้นสุด และขนาดห้อง
3. กรอกหัวข้อการประชุม
4. ถ้าต้องการให้ผู้อื่นช่วยดูแลห้องประชุม ให้กรอกอีเมลของผู้นั้นในช่อง Co-Host ได้หลายคน คั่นด้วยเครื่องหมายจุลภาค ต้องเป็นอีเมลของมหาวิทยาลัยเท่านั้น
5. กรอกหมายเหตุหรือเหตุผลการจองถ้ามี ช่องนี้สำคัญสำหรับห้องที่ต้องรออนุมัติ
6. ถ้าเป็นการประชุมที่จัดซ้ำ ให้เลือกจองซ้ำ แล้วเลือกว่าซ้ำทุกวันหรือทุกสัปดาห์และจำนวนครั้ง ทุกครั้งต้องอยู่ภายใน 30 วันและนับรวมในโควตา
7. ถ้านัดประชุมกับผู้เข้าร่วมต่างประเทศ เลือกเขตเวลาที่ใช้กรอกเวลาก่อน แล้วกรอกวันและเวลาเป็นเวลาของประเทศนั้นได้เลย ระบบจะแสดงว่าตรงกับเวลาไทยกี่โมง และคำเชิญของ Zoom กับอีเมลแจ้งเตือนจะแสดงเวลาตามเขตนั้นด้วย เวลาที่เลือกยังต้องอยู่ในช่วง 08.00 ถึง 24.00 น. เวลาไทย
8. กดยืนยันการจอง

เมื่อจองสำเร็จ ระบบจะส่งอีเมลยืนยันพร้อมลิงก์ห้องประชุม และเพิ่มนัดหมายลง Google Calendar ของผู้จอง

## การจองที่ต้องรออนุมัติ

- การจองห้อง 300 หรือ 1000 คนจะมีสถานะรออนุมัติ ระบบจะแจ้งผู้ดูแลทางอีเมล
- เมื่อผู้ดูแลอนุมัติหรือปฏิเสธ ผู้จองจะได้รับอีเมลและการแจ้งเตือนในเว็บ
- ถ้าคำขอค้างเกิน 1 ชั่วโมง ระบบจะเตือนผู้ดูแลซ้ำทุก 6 ชั่วโมง และทุก 2 ชั่วโมงเมื่อใกล้ถึงวันประชุม
- ถ้าถึงเวลาประชุมแล้วยังไม่มีผู้อนุมัติ ระบบจะยกเลิกคำขอนั้นอัตโนมัติและคืนโควตาให้
- ผู้จองยกเลิกคำขอที่ยังรออนุมัติเองได้ที่เมนูการจองของฉัน
- ควรจองห้องขนาดใหญ่ล่วงหน้าหลายวันเพื่อให้ผู้ดูแลมีเวลาพิจารณา

## การเข้าห้องประชุม

1. ไปที่เมนูการจองของฉัน
2. กดปุ่มเข้าร่วม Zoom ที่รายการประชุม
3. ผู้จองจะเข้าห้องในฐานะผู้ดำเนินการประชุม หรือ Host

ปุ่มเข้าห้องจะใช้ได้เมื่อถึงเวลาเริ่มประชุมเท่านั้น ก่อนหน้านั้นระบบจะแจ้งว่ายังไม่ถึงเวลา

ก่อนเริ่มประชุม 15 นาที ระบบจะส่งอีเมลแจ้งเตือนพร้อมลิงก์ห้องประชุม

ข้อควรระวัง ส่งลิงก์ห้องประชุมให้เฉพาะผู้ที่เกี่ยวข้องเท่านั้น และไม่ควรเผยแพร่ลิงก์ในช่องทางสาธารณะ

## การยกเลิกการจอง

1. ไปที่เมนูการจองของฉัน
2. กดยกเลิกที่รายการที่ต้องการ
3. ถ้าเป็นการจองซ้ำ เลือกได้ว่าจะยกเลิกเฉพาะครั้งนี้หรือทั้งชุด

การยกเลิกจะคืนโควตาให้ และระบบจะลบนัดหมายออกจาก Google Calendar พร้อมส่งอีเมลแจ้ง

## ไฟล์บันทึกการประชุม

ถ้ามีการบันทึกการประชุมลง Zoom Cloud ระหว่างประชุม หลังประชุมจบระบบจะดึงไฟล์วิดีโอ เสียง ข้อความแชท และคำบรรยาย ไปเก็บไว้ในโฟลเดอร์ชื่อ KU Zoom Bookings ใน Google Drive ของผู้จอง เมื่อไฟล์พร้อมจะมีการแจ้งเตือนในเว็บ และกดดาวน์โหลดได้จากเมนูการจองของฉัน

Zoom ใช้เวลาประมวลผลไฟล์บันทึกประมาณเท่ากับความยาวของการประชุม ไฟล์จึงอาจยังไม่มาทันทีหลังประชุมจบ

# ส่วนที่ 2 คู่มือผู้ดูแลระบบ

## ภาพรวมของระบบ

| ส่วน | เทคโนโลยี | ตำแหน่งในโปรเจกต์ |
|---|---|---|
| หน้าเว็บ | React และ Vite | frontend/ |
| เซิร์ฟเวอร์ | Node.js และ Express | src/ |
| ฐานข้อมูล | PostgreSQL | migrations/ |
| การส่งอีเมล | n8n รับข้อมูลผ่าน webhook แล้วส่งอีเมล | อยู่นอกโปรเจกต์นี้ |

บริการภายนอกที่ระบบเชื่อมต่อ

- Zoom ใช้สร้างและลบห้องประชุม และรับแจ้งเหตุการณ์ต่าง ๆ เช่น ประชุมเริ่ม ประชุมจบ หรือไฟล์บันทึกพร้อม
- Google ใช้ยืนยันตัวตน บันทึกนัดหมายลง Calendar และอัปโหลดไฟล์ลง Drive
- KU ALL-Login ระบบยืนยันตัวตนกลางของมหาวิทยาลัย ดูแลโดยสำนักบริการคอมพิวเตอร์
- n8n รับข้อมูลจากระบบแล้วส่งอีเมลถึงผู้ใช้

## โครงสร้างโฟลเดอร์

```
config/db.js                  การเชื่อมต่อฐานข้อมูล
migrations/                   ไฟล์ SQL สำหรับสร้างและปรับตาราง เรียงตามลำดับเลข
src/server.js                 จุดเริ่มต้นของเซิร์ฟเวอร์และงานตั้งเวลา
src/app.js                    ตั้งค่า Express เส้นทาง และการจำกัดจำนวนคำขอ
src/middleware/               ตรวจ token และตรวจสิทธิ์ staff กับ admin
src/routes/auth.js            การเข้าสู่ระบบด้วย Google และ KU ALL-Login
src/routes/bookings.js        การจอง ดูห้องว่าง ยกเลิก เข้าห้อง
src/routes/admin.js           หน้าผู้ดูแล สถิติ อนุมัติ จัดการผู้ใช้ ห้อง และบัญชี Zoom
src/routes/notifications.js   การแจ้งเตือนในเว็บ
src/routes/zoomWebhook.js     รับเหตุการณ์จาก Zoom
src/services/                 ตรรกะหลักของระบบ แยกไฟล์ตามหน้าที่
frontend/src/pages/           หน้าเว็บแต่ละหน้า
frontend/src/components/      ส่วนประกอบที่ใช้ร่วมกัน เช่น แถบเมนูและกระดิ่งแจ้งเตือน
```

| auditService.js | บันทึกประวัติการกระทำสำคัญ |

## สิทธิ์ผู้ใช้

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| student | ผู้ใช้ทั่วไป ทุกคนที่เข้าระบบครั้งแรกจะได้สิทธิ์นี้ จองได้ 4 ครั้งต่อเดือน |
| priority | ไม่จำกัดจำนวนครั้งต่อเดือน แต่จองรวมได้ไม่เกิน 40 ชั่วโมงต่อสัปดาห์ และใช้ห้องที่สงวนไว้ให้กลุ่มนี้ได้ |
| staff | อนุมัติหรือปฏิเสธคำขอ ดูรายการจองทั้งหมด ยกเลิกการจองของผู้อื่นโดยต้องระบุเหตุผล ย้ายห้อง และดูประวัติการใช้งาน |
| admin | ทำได้ทุกอย่างของ staff และเพิ่มเติมคือ เปลี่ยนสิทธิ์ผู้ใช้ จัดการห้องและบัญชี Zoom โอนการจอง ส่งออกข้อมูลเป็นไฟล์ CSV ไม่ติดโควตา และจองล่วงหน้าเกิน 30 วันได้ |

## การติดตั้งบนเครื่องสำหรับพัฒนา

สิ่งที่ต้องมี

- Node.js รุ่น 20 ขึ้นไป
- PostgreSQL รุ่น 15 ขึ้นไป
- Git

ขั้นตอน

1. ดึงโค้ด

```
git clone https://github.com/Monkeydono/KUZ.git
cd KUZ
```

2. ติดตั้งแพ็กเกจของเซิร์ฟเวอร์และหน้าเว็บ

```
npm install
npm --prefix frontend install
```

3. สร้างฐานข้อมูลชื่อ KUZ แล้วรันไฟล์ migration ทุกไฟล์ตามลำดับเลข

```
psql -U postgres -c "CREATE DATABASE \"KUZ\";"
for f in migrations/*.sql; do psql -U postgres -d KUZ -v ON_ERROR_STOP=1 -f "$f"; done
```

4. คัดลอกไฟล์ตั้งค่าแล้วกรอกค่าให้ครบ รายละเอียดอยู่ในหัวข้อถัดไป

```
cp .env.example .env
cp frontend/.env.example frontend/.env
```

5. เปิดเซิร์ฟเวอร์และหน้าเว็บ โดยเปิดหน้าต่าง terminal แยกกัน 2 หน้าต่าง

```
npm run dev
npm run frontend
```

เซิร์ฟเวอร์ทำงานที่ http://localhost:3000 และหน้าเว็บทำงานที่ http://localhost:5173

## การตั้งค่า KU ALL-Login

- ขอใช้บริการโดยส่งแบบฟอร์มถึงสำนักบริการคอมพิวเตอร์ ติดต่อ admin@ku.ac.th
- KU ALL-Login บังคับใช้ https ทั้ง redirect URI และ logout redirect URI
- ค่า redirect URI ของเซิร์ฟเวอร์จริงคือ https://meet.ocs.ku.ac.th/calendar และ logout redirect URI คือ https://meet.ocs.ku.ac.th/logout
- ข้อมูลผู้ใช้ที่ได้รับขึ้นอยู่กับ scope ที่สำนักบริการคอมพิวเตอร์อนุมัติให้ ถ้าเข้าสู่ระบบไม่สำเร็จ ให้ดู log ของเซิร์ฟเวอร์ที่ขึ้นต้นด้วย kulogin exchange ซึ่งจะแสดงรายชื่อข้อมูลที่ได้รับจริง
- ระบบใช้อีเมลในข้อมูล google-mail เป็นตัวเชื่อมกับบัญชี Google ของผู้ใช้คนเดียวกัน
- ข้อมูลที่เก็บจาก KU ALL-Login อยู่ในตาราง users ได้แก่ ประเภทบุคคลในคอลัมน์ ku_type_person คณะและภาควิชาของบุคลากรในคอลัมน์ ku_faculty, ku_faculty_code, ku_department, ku_department_code รหัสคณะของนิสิตในคอลัมน์ ku_major_id วิทยาเขตในคอลัมน์ ku_campus และเวลาที่ยืนยันตัวตนล่าสุดในคอลัมน์ ku_profile_at
- ประเภทบุคคล 4 คือศิษย์เก่า และ 5 คือบุคคลภายนอก จะเข้าระบบไม่ได้ ยกเว้นอีเมลที่อยู่ใน ADMIN_EMAILS
- ผู้ที่เข้าด้วย Google แต่ยังไม่เคยยืนยันตัวตนผ่าน KU ALL-Login จะถูกพาไปยืนยันตัวตนก่อน ผู้ใช้เดิมทุกคนจึงต้องเข้าด้วย KU ALL-Login หนึ่งครั้งหลังอัปเดตระบบนี้
- KU ALL-Login ยอมรับเฉพาะ redirect URI ที่ลงทะเบียนไว้ คือของเซิร์ฟเวอร์จริง จึงทดสอบการเข้าสู่ระบบด้วย KU ALL-Login บนเครื่องพัฒนาไม่ได้ ถ้าต้องการทดสอบบนเครื่องพัฒนาต้องขอสำนักบริการคอมพิวเตอร์เพิ่ม redirect URI ของเครื่องพัฒนา

## การตั้งค่า n8n

ระบบไม่ได้ส่งอีเมลเอง แต่ส่งข้อมูลการจองไปยัง webhook ของ n8n แล้ว n8n เป็นผู้จัดรูปแบบและส่งอีเมล

- ผู้ส่งอีเมล เนื้อหาอีเมล และเซิร์ฟเวอร์ SMTP ตั้งค่าใน n8n ไม่ได้อยู่ในโค้ดนี้
- แต่ละเหตุการณ์ใช้ workflow แยกกัน และแต่ละ workflow มี URL ของตัวเอง นำ URL มาใส่ในตัวแปร N8N_ ที่ตรงกันในไฟล์ .env
- ข้อมูลที่ระบบส่งไปแต่ละแบบดูได้ที่ src/services/notificationService.js
- ข้อมูลที่เพิ่มในรอบแก้ไขที่ 1 คือ guest_timezone และ guest_time สำหรับแสดงเวลาของผู้เข้าร่วมต่างชาติในอีเมล และ is_reminder กับ hours_until_start ในคำขอรออนุมัติ เพื่อให้อีเมลเตือนซ้ำใช้หัวเรื่องต่างจากอีเมลคำขอใหม่ ต้องแก้ template ใน n8n ให้ใช้ข้อมูลเหล่านี้
- เมื่อย้าย n8n ไปยังพื้นที่ใหม่ ให้ส่งออก workflow จากที่เดิม นำเข้าที่ใหม่ ตั้งค่า SMTP ใหม่ แล้วเปลี่ยน URL ทั้งหมดในไฟล์ .env

## การแก้ไขฐานข้อมูล

- ห้ามแก้ไฟล์ migration ที่เคยรันบนเซิร์ฟเวอร์จริงแล้ว ให้สร้างไฟล์ใหม่ต่อท้ายด้วยเลขถัดไปเสมอ เช่น 019_ชื่อการเปลี่ยนแปลง.sql
- เขียนคำสั่งให้รันซ้ำได้โดยไม่เกิดข้อผิดพลาด เช่น ใช้ IF NOT EXISTS
- ขึ้นต้นไฟล์ด้วย SET client_encoding = 'UTF8'; เพื่อให้ข้อความภาษาไทยถูกต้อง
- ระบบไม่มีเครื่องมือรัน migration อัตโนมัติ ต้องรันไฟล์ใหม่ด้วย psql เองทั้งบนเครื่องพัฒนาและเซิร์ฟเวอร์จริง
- สำรองฐานข้อมูลก่อนรัน migration บนเซิร์ฟเวอร์จริงทุกครั้ง

```
pg_dump -U postgres -d KUZ -F c -f kuz_backup.dump
```

## การนำขึ้นเซิร์ฟเวอร์จริง

เซิร์ฟเวอร์จริงเป็นเครื่อง Linux ภายในเครือข่ายของมหาวิทยาลัย ใช้ Nginx อยู่ด้านหน้าและใช้ pm2 ควบคุมการทำงานของเซิร์ฟเวอร์ Node.js

1. เชื่อมต่อเข้าเซิร์ฟเวอร์ผ่าน SSH ด้วยโปรแกรม PuTTY แล้วไปที่โฟลเดอร์ของโปรเจกต์
2. ดึงโค้ดล่าสุดด้วย git pull
3. ติดตั้งแพ็กเกจด้วย npm install และ npm --prefix frontend install
4. รัน migration ใหม่ถ้ามี
5. สร้างหน้าเว็บด้วย npm --prefix frontend run build จะได้ไฟล์ในโฟลเดอร์ frontend/dist ให้ Nginx นำไปแสดง
6. เริ่มเซิร์ฟเวอร์ใหม่ด้วย pm2 restart ตามชื่อที่ตั้งไว้ใน pm2

ข้อควรระวัง

- ต้องรัน pm2 แบบ instance เดียวเท่านั้น ห้ามใช้ cluster mode เพราะ KU ALL-Login เก็บข้อมูลระหว่างขั้นตอนเข้าสู่ระบบไว้ในหน่วยความจำ ถ้ามีหลาย instance การเข้าสู่ระบบจะล้มเหลวด้วยข้อความ invalid_state
- Nginx ต้องส่ง header X-Forwarded-For มาด้วย ตรวจได้โดยเปิด /health จากเครื่องภายนอก ค่า ip ที่ได้ต้องเป็น IP จริงของเครื่องนั้น ถ้าได้ 127.0.0.1 แปลว่าตั้งค่าไม่ถูก และผู้ใช้ทั้งมหาวิทยาลัยจะถูกนับรวมในการจำกัดจำนวนคำขอเดียวกัน
- ตั้ง NODE_ENV=production บนเซิร์ฟเวอร์จริง

## การแก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| เซิร์ฟเวอร์เปิดไม่ขึ้น ขึ้นข้อความ OAuth2Strategy requires a clientID option | ยังไม่ได้กรอก GOOGLE_CLIENT_ID ในไฟล์ .env |
| เซิร์ฟเวอร์ขึ้นข้อความ Database connection failed | PostgreSQL ไม่ทำงาน หรือค่าการเชื่อมต่อใน .env ไม่ถูกต้อง |
| KU ALL-Login ขึ้น Client not found หรือ Invalid redirect_uri | client ID, realm หรือ redirect URI ไม่ตรงกับที่ลงทะเบียนไว้ ดูค่าที่ส่งไปจริงได้จาก log ที่ขึ้นต้นด้วย kulogin authorize |
| KU ALL-Login ขึ้น invalid_state | pm2 ทำงานแบบหลาย instance หรือเซิร์ฟเวอร์เริ่มใหม่ระหว่างที่ผู้ใช้กำลังเข้าสู่ระบบ |
| ผู้ใช้ถูกพากลับหน้าเข้าสู่ระบบพร้อมข้อความว่ามีคำขอมากเกินไป | เกินการจำกัดจำนวนคำขอ ให้ตรวจ X-Forwarded-For ตามหัวข้อก่อนหน้า |
| อีเมลไม่ถูกส่ง | ดู log ที่ขึ้นต้นด้วยชื่อเหตุการณ์ เช่น booking_created ถ้าขึ้นว่า not configured แปลว่ายังไม่ได้ใส่ URL ของ n8n ถ้าขึ้นว่า FAILED ให้ตรวจ workflow ใน n8n |
| นัดหมายไม่ขึ้นใน Google Calendar | ผู้ใช้ยังไม่ได้อนุญาตสิทธิ์ Calendar หรือสิทธิ์หมดอายุ ให้ผู้ใช้ออกจากระบบแล้วเข้าด้วย Google ใหม่ |
| ไฟล์บันทึกการประชุมไม่มา | ตรวจว่าเปิดการบันทึกลง Zoom Cloud ระหว่างประชุม ตรวจว่าแอป Zoom ส่งเหตุการณ์ recording.completed มาที่ระบบ ดูได้จากแท็บ Audit และตรวจว่าผู้จองอนุญาตสิทธิ์ Drive แล้ว |
